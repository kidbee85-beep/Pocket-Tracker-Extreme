# Companion processes and corresponding source

The Brick package is an aggregate of the GPL application and independent companion tools. It does not replace or redistribute KNULLI's system SDL, curl or FFmpeg. See `external/helper-provenance.json` for exact binary/source hashes and `licenses/` in the binary ZIP for the notices.

## yt-dlp

The bundled executable is the **unmodified official yt-dlp2026.10.26 LinuxARM64 PyInstaller build**, SHA256 `e87e9533e89fe5889abaa21f5114dfe7756d6aa6219b83551add04d48b18e483`.

The matching yt-dlp source archive is `external/yt-dlp-2026.10.26.tar.gz`. The complete upstream license texts are `external/yt-dlp-LICENSE` and `external/yt-dlp-THIRD_PARTY_LICENSES.txt`. The combined official executable is GPL-3.0-or-later; yt-dlp's own source is under the Unlicense.

An isolated ARM64 runtime probe recorded CPython3.14.10, OpenSSL3.5.9, Cryptodome3.24.1, brotli1.2.1, certifi2026.10.23, curl_cffi0.17.0, mutagen1.48.1, requests2.34.2, secretstorage3.5.0, sqlite3.54.1, urllib3 2.8.0, websockets17.3 and yt_dlp_ejs0.8.0. It ran without networking; the deliberately invalid extraction URL failed as expected, after reporting the versions.

`external/yt-dlp-bundle-sources/` supplies pinned Python package source distributions, CPython and OpenSSL source archives, with exact download URLs and SHA256 hashes in `SOURCE-MANIFEST.json`. This includes mutagen and PyInstaller source as well as the source archives for the recorded optional packages and their Python dependencies. Each source archive retains its original license files. The yt-dlp source's pinned dependency/build descriptions and the upstream source links in the full third-party notices explain its build inputs; this is not a claim that another compiler necessarily produces a byte-identical upstream executable.

## QuickJS

`external/quickjs-2026-06-04.tar.xz` contains the exact MIT-licensed source. `external/build-quickjs.py` rebuilds it for ARM64Linux/glibc2.31 with Zig0.14.1 and a host C compiler. Public builds map private compiler paths and use the relative `repl.js` name in its generated bytecode. The engine and syntax remain the same.

## Experimental iPhone tools

`external/iphone-usb` and `external/iphone-pair` contain the Go source and vendored dependencies. `external/apple-usb-deps` contains libusb1.0.30, libplist2.8.1 and usbmuxd1.1.1 source, including their full license texts. `tools/brick/build_iphone.py` builds the tools with Go1.27.3 and Zig0.14.1; its `--libusb-source` switch permits rebuilding against a modified libusb copy. The private build paths are mapped and the C executable is stripped in public builds.

These tools remain experimental. A software protocol check does not establish compatibility with an actual iPhone, its trust/pairing state or the device's USB role. Pairing records must remain local and are excluded from releases.

## Android Java runtime sources

Frozen NewPipe extraction sources and generated Protobuf inputs are in `vendor/newpipe-extractor`. `PROVENANCE.json`, the pinned Gradle dependencies and `docs/licenses/NewPipe-PROVENANCE.txt` identify their exact revisions. Additional Rhino1.8.1/RhinoEngine source JARs and the desugared JDK source revision used for version2.1.5 are supplied in `external/android-dependency-sources`, with a source manifest. The desugared JDK source revision is the official change preparing version2.1.5; its original Git history and files retain their license notices. The Android SDK, NDK and build tools are separately obtained general development tools, not part of the APK release.

## CA certificates

The supplied CA bundle and its Mozilla/MPL-2.0 notices are in `external`. Their provenance/hash is recorded in `external/helper-provenance.json`. No certificate validation is disabled for online features.
